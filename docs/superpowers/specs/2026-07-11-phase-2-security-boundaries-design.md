# Clade 第二阶段安全边界设计

日期：2026-07-11
状态：待用户审阅
范围：本地网络边界、AI 密钥、管理操作、存档路径、外部 URL 访问

## 1. 目标

将 Clade 明确收敛为默认只在本机使用的应用，并阻断五类已确认的风险：局域网意外暴露、API Key 回显、无保护的破坏性管理操作、存档路径越界，以及由自定义 AI 地址触发的服务端请求伪造。

本阶段不改变模拟规则、回合计算、数据库结构、存档数据格式或 AI 路由逻辑。合法的历史存档、云端 AI 服务和用户明确启用的本地模型服务必须继续可用。

## 2. 执行方式

采用三批独立提交，每批均可单独验证和回退：

1. A 批：本机监听与密钥脱敏。
2. B 批：管理操作与存档路径保护。
3. C 批：外部 URL 访问策略与 SSRF 防护。

不采用一次性大改，因为五条路径的失败模式不同；分批后，网络、配置、文件和外部请求问题可以分别定位。

## 3. A 批：本机监听与密钥脱敏

### 3.1 网络监听

标准启动脚本 `start.ps1` 将后端监听地址由 `0.0.0.0` 改为 `127.0.0.1`，前端开发服务器也显式绑定 `127.0.0.1`。README 中的启动命令同步更新。

增加以下环境配置：

- `BACKEND_HOST`：默认 `127.0.0.1`。
- `FRONTEND_HOST`：默认 `127.0.0.1`。
- `ALLOW_LAN_ACCESS`：默认 `false`。

只有 `ALLOW_LAN_ACCESS=true` 时才允许非回环监听。启动脚本必须打印醒目的局域网风险提示，不能仅通过设置 `BACKEND_HOST=0.0.0.0` 绕过开关。

### 3.2 配置读取

持久化配置仍由 `UIConfig` 表示，但 API 响应不得直接返回持久化对象。新增配置脱敏函数，返回与现有前端结构兼容的公开字典：

- `providers.*.api_key` 固定返回空字符串。
- 每个服务商增加 `api_key_configured: boolean`。
- 旧字段 `ai_api_key`、`embedding_api_key` 固定返回空字符串。
- 增加对应的 `*_configured` 布尔标记。

脱敏只发生在 API 边界，不修改内存中的运行配置，也不重写磁盘文件。

### 3.3 配置更新

前端加载配置后不再持有服务端已有密钥。保存时采用以下语义：

- API Key 为空或未提供：保留磁盘中的原值。
- API Key 为新非空值：替换原值。
- 用户明确点击“清除密钥”：通过 `clear_provider_api_keys` 列表请求删除对应密钥。

配置更新请求使用明确的封装结构：

```json
{
  "config": {},
  "clear_provider_api_keys": []
}
```

后端在验证和保存前，将公开配置与现有秘密字段合并。接口响应始终再次脱敏。前端输入框用“已配置”状态提示已有密钥，不用星号伪造一个可再次提交的密钥值。

## 4. B 批：管理操作与存档路径保护

### 4.1 管理令牌

所有会修改或删除数据的 `/api/admin` 端点增加统一依赖 `require_admin_token`。只读健康检查和存储统计不需要令牌。

令牌来源为环境变量 `CLADE_ADMIN_TOKEN`：

- 未配置时，破坏性管理端点返回 `503`，而不是无保护执行。
- 令牌错误或缺失时返回 `403`。
- 使用常量时间比较，日志中不记录令牌。
- 前端管理面板仅在用户执行管理操作时要求输入令牌，并只保存在当前组件内存中。
- 请求通过 `X-Clade-Admin-Token` 发送；不写入 localStorage、配置文件或 URL。

`start.ps1` 不把令牌编译进前端，也不自动暴露令牌。用户需要管理功能时，可在启动前显式设置环境变量，并在管理面板输入同一值。

### 4.2 管理端点范围

以下端点必须保护：重置世界、删除并重建数据库、数据库优化、清理历史、创建索引，以及后续加入 `/api/admin` 的所有非 GET/HEAD 请求。保护逻辑应用在路由层，避免遗漏单个函数。

普通游戏中的存档删除不复用管理员令牌，以免破坏主要使用流程；它由前端二次确认、严格名称校验和目录边界校验共同保护。

### 4.3 存档名称与目录边界

新增单一的存档名称校验模块，供请求模型和 `SaveManager` 共同使用：

- 长度为 1–50 个字符。
- 允许 Unicode 字母、数字、空格、`_` 和 `-`。
- 拒绝 `.`、`..`、正斜杠、反斜杠、绝对路径、控制字符和尾随空格/点。
- 拒绝 Windows 设备名，如 `CON`、`NUL`、`COM1`、`LPT1`。

`SaveManager` 在创建、保存、加载、删除、完整性检查和迁移入口统一调用校验。任何候选目录都必须执行 `resolve()`，并验证最终路径仍位于已解析的 `saves_dir` 内。

兼容策略：历史存档继续通过 `metadata.json` 中的显示名称查找；现有 `save_时间_名称` 文件夹无需改名。非法输入返回明确的 422/400 错误，不能静默改成另一个名称。

## 5. C 批：外部 URL 与 SSRF 防护

### 5.1 集中策略

新增 `OutboundURLPolicy`，`/api/config/test-api` 和 `/api/config/fetch-models` 必须在发起请求前调用。后续其他用户可配置的服务端外部请求也复用该策略。

默认规则：

- 仅允许 `https`。
- 拒绝 URL 用户名或密码、空主机、异常端口和非 HTTP(S) 协议。
- DNS 解析后拒绝回环、链路本地、私有、保留、多播和未指定地址。
- 禁止自动重定向；若以后允许重定向，每一跳都必须重新校验。
- 响应正文最多读取 1 MiB。
- 错误响应不回显请求头、API Key、完整内部异常或超量正文。

### 5.2 本地模型例外

Ollama、LM Studio 等本地服务仅在 `ALLOW_LOCAL_AI_ENDPOINTS=true` 时允许。例外范围只包含回环主机 `127.0.0.1`、`::1` 和 `localhost`，不自动放开整个私有网段。

本地开发可额外允许 `http`，但仍禁止 URL 凭据和非回环私有地址。前端检测到本地地址但开关未启用时，应显示可操作的说明，而不是普通“连接失败”。

### 5.3 请求实现

外部请求使用集中封装，统一设置连接、读取和总超时；显式关闭重定向；以流式方式读取受限响应。Google 将 API Key 放在查询参数的现有调用也不得将完整 URL 写入日志或错误响应。

## 6. 数据流

配置读取流程：磁盘完整配置 → Pydantic 校验 → API 脱敏 → 前端仅持有公开状态。

配置保存流程：前端公开配置与可选新密钥 → 后端读取当前完整配置 → 按“保留/替换/清除”合并 → 校验并原子保存 → 返回脱敏结果。

存档流程：API 输入 → 名称校验 → `SaveManager` 再校验 → 候选路径解析与目录包含检查 → 文件操作。

外部请求流程：用户配置 → URL 语法校验 → DNS/IP 校验 → 受限 HTTP 请求 → 受限响应解析 → 脱敏错误。

## 7. 错误处理

- 无效配置或存档名称：`422`，返回不含敏感数据的具体原因。
- 管理令牌未配置：`503`。
- 管理令牌缺失或错误：`403`，不区分两种情况。
- URL 被策略拒绝：`400`，返回规则层面的说明。
- 外部服务超时或不可达：`502/504`，不返回底层请求头或完整内部异常。
- 配置保存失败：保留原文件，不在失败后刷新运行时 ModelRouter。

配置文件保存应采用同目录临时文件加原子替换，避免进程中断留下半个 JSON 文件。

## 8. 测试与验收

### 8.1 自动测试

- 启动脚本与配置测试：默认主机为回环地址；没有显式开关时拒绝非回环监听。
- 脱敏测试：GET、POST 响应及错误日志均不含真实密钥。
- 合并测试：空值保留、新值替换、明确清除三种情况。
- 管理端点测试：无令牌、错误令牌、正确令牌和未配置四种情况。
- 存档属性测试：遍历 `../`、绝对路径、Windows 设备名、Unicode 合法名和历史存档。
- URL 策略测试：公网 HTTPS、HTTP、本机、私网、IPv6、DNS 解析、凭据、重定向和超量响应。
- 前端测试：已配置状态、输入新密钥、明确清除和管理令牌不持久化。

### 8.2 每批共同门槛

- 前端 `npm run lint`、`npm run test:run`、`npm run build` 通过。
- 后端新增相关测试通过，完整 pytest 能收集 366 个或更多测试。
- 完整后端测试中的历史失败数量不得增加。
- `git diff --check` 通过。

### 8.3 最终验收

- 默认情况下其他局域网设备无法访问前后端。
- API、前端状态、日志和错误响应中不存在完整 API Key。
- 无有效管理令牌不能执行破坏性管理员操作。
- 所有路径穿越输入被拒绝，合法历史存档仍可加载。
- 默认不能请求本机、私网或非 HTTPS 外部地址。
- 显式启用后，回环地址上的本地模型仍能测试并获取模型列表。

## 9. 非目标与限制

- 本阶段不建设多用户账号、远程登录、权限角色或公网部署能力。
- 不使用系统钥匙串重构密钥存储；本阶段先消除 API 回显和意外传播。磁盘配置加密可作为后续独立工作。
- 不保护用户主动安装的恶意前端代码或拥有本机文件权限的攻击者。
- 不修改旧 `api/routes.py` 的迁移架构；实际已注册的新路由先完成安全收口，旧路由清理留在架构阶段。
